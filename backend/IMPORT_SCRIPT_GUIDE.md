# 词书导入脚本使用指南

**脚本位置**: `backend/import-wordbook.ts`  
**创建日期**: 2025年10月30日  
**版本**: v2.0 - 完整导入系统（任务1-12已完成）

---

## 📖 目标

为项目导入权威词书（四级、六级、托福等），并把数据存入中央词库，按词书打标签。支持完整的五层数据结构导入和智能去重。

---

## 🚀 快速开始

### 1. 基本使用

```bash
# 进入 backend 目录
cd backend

# 导入词书数据
npx ts-node import-wordbook.ts --book "词书名称" --file ../data/cet4-sample.json
```

### 2. 使用 npm 脚本

```bash
# 在 backend 目录下
npm run import-wordbook -- --book "大学英语四级核心词汇" --file ../data/cet4-sample.json
```

### 3. 试运行模式（推荐先使用）

```bash
# 不写入数据库，只验证数据格式
npx ts-node import-wordbook.ts --book "测试" --file ../data/cet4-sample.json --dry-run
```

## 📋 命令行参数

| 参数 | 必填 | 说明 | 示例 |

| `--book` | ✅ | 词书名称 | `--book "大学英语四级核心词汇"` |

## ⚠️ 错误处理

### 常见错误及解决方案

#### 1. 缺少必填参数

```
❌ 错误：缺少必填参数

使用方法：
  npm run import-wordbook -- --book "词书名称" --file ./data/cet4.json
```

**解决**: 确保同时提供 `--book` 和 `--file` 参数

#### 2. 文件不存在

```
❌ 错误：文件不存在 - D:\桌面\语境记忆\backend\not-exist.json
```

**解决**: 检查文件路径是否正确，使用相对路径或绝对路径

#### 3. JSON格式无效

```
❌ 错误：JSON格式无效
   Unexpected token } in JSON at position 123
```

**解决**: 使用 JSON 验证工具检查文件格式，确保是有效的 JSON

#### 4. 数据格式验证失败

```
❌ 单词条目[0] "test" 验证失败:
   - 缺少或无效的 partsOfSpeech 字段（必须是非空数组）
```

**解决**: 参考 `data/DATA_FORMAT_SPEC.md` 确保数据格式符合规范

## 📝 数据格式规范

### 标准JSON格式

每个单词条目的完整结构：

```json
{
  "word": "abandon",
  "phonetic": {"uk": "/əˈbændən/", "us": "/əˈbændən/"},
  "partsOfSpeech": [
    {
      "pos": "verb",
      "meanings": [
        {
          "definition": "放弃；抛弃",
          "difficulty": 2,
          "examples": ["He abandoned his car in the snow."]
        }
      ]
    }
  ]
}
```

### 必须提供的字段

- `word` (string): 单词原文，建议小写
- `partsOfSpeech` (array): 至少一个词性
  - `pos` (string): 词性（如 verb, noun, adj, adv）
  - `meanings` (array): 至少一个词义
    - `definition` (string): 中文释义

### 可选字段

- `phonetic` (object): 音标
  - `uk` (string): 英式音标
  - `us` (string): 美式音标
- `difficulty` (number): 难度等级 (1-5)
- `examples` (array): 例句列表（字符串数组）

### 数据准备建议

1. 使用 `data/template.json` 作为模板
2. 参考 `data/cet4-sample.json` 查看实际示例
3. 完整格式说明见 `data/DATA_FORMAT_SPEC.md`

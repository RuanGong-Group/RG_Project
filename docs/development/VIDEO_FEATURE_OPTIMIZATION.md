# 视频生成功能优化方案 (Video Feature Optimization)

**日期**: 2025-11-29
**状态**: 已确认

## 1. 核心逻辑

### 1.1 选词策略
*   **目标数量**: 固定 **7个单词**。
*   **优先级**:
    1.  **今日已完成学习的新单词** (Today's Learned New Words)。
    2.  如果不足 7 个，从 **待复习单词** (Due Reviews) 中补齐。
    3.  如果总数仍不足 7 个，则使用所有可用单词。
*   **前置条件**: 用户必须完成今日的新词学习任务后才能生成视频。如果未完成，点击按钮时提示“请先完成今日学习”。

### 1.2 生成限制与存储
*   **每日限制**: 每日仅允许生成 **1次**。
*   **重复点击**: 如果用户当日已生成过视频，再次点击按钮时，直接展示第一次生成的视频，**不触发**新的生成 API 调用。
*   **存储策略**:
    *   仅保留 **当日** 生成的视频。
    *   系统每日凌晨自动清理（删除）昨日及之前的视频文件。
    *   数据库保留生成记录，但标记文件路径为已清理。

## 2. 用户界面 (UI/UX)

### 2.1 入口位置
*   **页面**: `HomePage.tsx` (今日计划/学习主页)。
*   **位置**: 与“开始学习”、“开始复习”、“学习统计”等功能按钮并列。
*   **按钮文案**:
    *   未生成过: "🎬 生成今日视频"
    *   已生成过: "🎬 观看今日视频"

### 2.2 交互流程
1.  用户点击 **[🎬 生成今日视频]**。
2.  **检查**:
    *   是否已完成今日学习？ -> 否：弹窗提示“请先完成今日学习”。
    *   是否已生成过？ -> 是：直接跳转至播放页面。
3.  **生成中**:
    *   显示生成进度弹窗 (Progress Modal)。
    *   轮询状态接口。
4.  **生成完成**:
    *   自动跳转至 **视频播放页面**。

### 2.3 视频播放页面
*   **路由**: `/daily-video`
*   **布局**: 极简设计。
*   **核心元素**:
    *   全屏/大尺寸视频播放器。
    *   (可选) 视频包含的单词列表。
    *   返回按钮。

## 3. 后端 API 变更

### 3.1 新增接口
*   `GET /api/learning/today-new-words`: 获取今日已完成学习的新单词（用于前端判断是否满足生成条件，或仅在后端校验）。
*   `GET /api/video/today`: 检查今日是否已生成视频。如果存在，返回视频信息（路径、状态）。

### 3.2 修改接口
*   `POST /api/video/generate`:
    *   增加逻辑：检查今日是否已生成。如果是，直接返回现有任务信息。
    *   增加逻辑：检查是否完成今日学习。如果否，返回错误。
    *   增加逻辑：自动执行“7词选词策略”。

### 3.3 定时任务
*   新增 Cron Job：每天凌晨 02:00 清理 `createdAt < Today 00:00` 的视频文件。
